# Licensing, provenance and identity

**RP-03 record, checked 2026-10-21.** This is an engineering record of the terms
RackPy works under and the evidence behind them. It is not legal advice.
Questions that need a decision are collected under
[open questions](#open-questions-for-the-owner). The decisions themselves are in
[ADR 001](decisions/001-licensing-and-identity.md).

## Status at a glance

| Area | Status |
| --- | --- |
| RackPy's own code and docs | GPL-3.0-or-later (owner decision) |
| Using the Rack plugin API | Permitted: Rack is GPL-3.0-or-later and VCV recommends GPLv3+ plugins |
| Rack artwork, logo and name | Restricted; RackPy copies none of them |
| Ports of `helper.py` templates | **Clear** under GPL-3.0-or-later, with attribution |
| Examples for manual tutorial and API guide features | **Clear**: RackPy writes original examples and does not adapt manual code (owner decision, ADR 001) |
| Bundled CPython and binding library | Permissive and GPL-compatible; the exact files are audited per artifact |
| Name `RackPy` | Free on PyPI, conda-forge and the VCV Library; nothing registered |

## RackPy's license

All original RackPy work is GPL-3.0-or-later ([LICENSE](../LICENSE)). Files that
carry their own notice keep it. [NOTICE](../NOTICE) lists third-party material
and where its terms are recorded.

## Rack, the SDK and the plugin API

The pinned [Rack LICENSE.md](https://github.com/VCVRack/Rack/blob/061ccf63c1758599396ac1bb10d47345d9d34076/LICENSE.md)
(SHA-256 `24f503f4…d5f31`) says:

- Rack Free source and binaries are GPL-3.0-or-later.
- A "Non-Commercial Plugin License Exception" lets free-of-charge plugins use any
  license. RackPy does not rely on it, because RackPy is GPL-3.0-or-later.
- Plugins that copy significant non-API Rack code must be GPLv3. RackPy is.
- Component Library graphics are CC BY-NC 4.0.
- The visual design of the Core modules is CC BY-NC-ND 4.0.
- The VCV logo and icon may not be used in derivative works. "VCV" is a
  trademark, but "for VCV Rack" is acceptable for promoting a plugin.

The [Plugin Licensing](https://vcvrack.com/manual/PluginLicensing) page says a
GPLv3+ plugin is allowed and recommended, and that derivative works must stay
GPLv3. Its ethics guidelines forbid cloning brand names, model names, logos,
panel designs or component layouts.

The SDK's `LICENSE-dist` lists the libraries inside libRack: GLEW, GLFW
(zlib), jansson (MIT), OpenSSL (Apache-2.0), curl, Zstandard, libarchive,
speexdsp, libsamplerate, RtMidi, RtAudio, NanoVG and NanoSVG (zlib), Blendish
(MIT), osdialog (CC0), pffft, fuzzysearchdatabase (BSD-3-Clause),
ghc::filesystem (MIT), tinyexpr (zlib) and SIMDe (MIT). Rack distributes these
inside its own binaries. RackPy does not redistribute them.

## Official sample sources

[upstream/examples.json](../upstream/examples.json) gives every official
code sample a stable ID, a source anchor, a content hash, a classification and
an example task. It records **77 samples**: 69 code blocks from six manual pages and
8 templates generated by `helper.py`. Fourteen other manual pages contain no
code blocks and are listed as such.

`bin/manual-sources capture` downloads the pages into a cache outside git.
`bin/manual-sources check` re-derives every block hash and fails on any changed,
added or removed block. A change in the rest of the page is only reported.

### The manual's license is unclear

- No manual page **displays** any license.
- The manual index contains this statement **inside an HTML comment**, so
  readers never see it: "All documentation text in the VCV Manual under the
  `https://vcvrack.com/manual/` URL is licensed under CC BY-SA 4.0 … Images such
  as screenshots and logos are licensed by their respective owner."
- VCV publishes no public repository for the manual (checked
  `gh repo list VCVRack`), so no source revision or license file exists.
- A code search found no VCV-published GPL copy of the tutorial or guide code.

A hidden comment shows intent, but it is not clearly a published grant. The
owner therefore chose not to depend on it: **RackPy writes original examples**
for the features these samples demonstrate (`port_gate: original-example`)
and links to the manual sections. It does not copy or adapt the manual's code
or text. Shell commands, transcripts and configuration snippets get RackPy
equivalents in the same way. See ADR 001.

The recorded hashes still matter: they tell an example task which features the
live manual teaches, and `bin/manual-sources check` reports when that changes.

### `helper.py` templates are clear

`helper.py` is byte-identical in the SDK and in the pinned Rack tree
(`5d9f058e…1fa12`). Rack's license covers its source,
so the template text it generates is GPL-3.0-or-later. RP-33 may port the
`createplugin` and `createmodule` templates with an attribution header naming
the Rack commit and listing the changes.

### Errata found while classifying

RackPy's examples follow the pinned headers, not these mistakes. Where an
example's README compares itself to the manual section, it names the erratum:

| Sample | Upstream text | Problem |
| --- | --- | --- |
| `guide-08` | `onRandomize(const ResetEvent& e) override` | Wrong event type; does not compile. `migrate2-06` has the correct type. |
| `guide-18` | Comment "triangle with blue stroke" | The stroke is red |
| `guide-25` | `std::sin(2.f * M_PI * phase)` | Passes the array; must be `phase[c]` |
| `guide-30` | `float_t freq`, `simd::sin(2.f * M_PI * phase)` | Must be `float_4`, and `phase[c / 4]` |

## Components in RackPy artifacts

RP-04 chose pybind11 and python-build-standalone CPython 3.14
([ADR 002](decisions/002-embedding-and-bindings.md)); nanobind is listed because it
was evaluated. This table records the terms so that the choice can be checked. "Audit" means the
exact files in an artifact must be listed with their licenses before release.

| Component | License | Obligations in a binary artifact |
| --- | --- | --- |
| RackPy native host and Python package | GPL-3.0-or-later | Corresponding source for each release (below) |
| Rack header code compiled into the plugin (inline functions, templates) | GPL-3.0-or-later | Covered by the same source offer |
| `simd/sse_mathfun.h`, `sse_mathfun_extension.h` | zlib | Keep the notices (already in the headers) |
| SIMDe (compiled in on arm64) | MIT | Include the notice |
| jansson inline helpers | MIT | Include the notice |
| pybind11 | BSD-3-Clause | Include the notice |
| nanobind | BSD-3-Clause | Include the notice |
| CPython | PSF-2.0, GPL-compatible; docs examples 0BSD | Include `LICENSE`; audit bundled extension modules (OpenSSL, libffi, zlib, sqlite, …) |
| python-build-standalone builds | Build scripts MPL-2.0; each distribution bundles other libraries | Audit the distribution's own license metadata; do not assume |

GPL-3.0-or-later is compatible with Apache-2.0 (OpenSSL 3), the PSF license,
MIT, BSD and zlib. A component under GPL-2.0-only would not be, so the audit
must reject one.

## Source offer and notices

For each release, RackPy will publish the complete corresponding source as a
tagged commit and a source archive next to the binaries (GPLv3 section 6(d)).
Every binary artifact will contain:

- `LICENSE` (GPL-3.0-or-later) and `NOTICE`;
- a generated third-party license manifest for exactly the files it contains,
  including the bundled Python runtime and standard library;
- the Rack commit and SDK digest it was built against.

RP-39, RP-40 and RP-41 implement this per platform. RP-44 checks it before
release. Signing, publishing and registering names need owner approval.

unfinished package.

## Open questions for the owner

1. **User plugins written with RackPy.** User scripts run in the same process as
   GPL code and call it intimately. The FSF view is that such plugins are
   usually derivative works. Decide what RackPy's documentation tells plugin
   authors about licensing their scripts, and whether you want a linking or
   plugin exception for user scripts.
2. **Commercial use.** VCV's commercial plugin licence also covers the
   Component Library graphics. RackPy is GPL. Decide whether RackPy says anything
   about commercial plugins built with it.
