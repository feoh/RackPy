Licensing, provenance and identity¶

RP-03 record, checked 2026-10-21. This is an engineering record of the terms RackPy works under and the evidence behind them. It is not legal advice. Questions that need a decision are collected under open questions. The decisions themselves are in ADR 001.

RackPy’s license¶

All original RackPy work is GPL-3.0-or-later (LICENSE). Files that carry their own notice keep it. NOTICE lists third-party material and where its terms are recorded.

Rack, the SDK and the plugin API¶

The pinned Rack LICENSE.md (SHA-256 24f503f4…d5f31) says:

  • Rack Free source and binaries are GPL-3.0-or-later.

  • A “Non-Commercial Plugin License Exception” lets free-of-charge plugins use any license. RackPy does not rely on it, because RackPy is GPL-3.0-or-later.

  • Plugins that copy significant non-API Rack code must be GPLv3. RackPy is.

  • Component Library graphics are CC BY-NC 4.0.

  • The visual design of the Core modules is CC BY-NC-ND 4.0.

  • The VCV logo and icon may not be used in derivative works. “VCV” is a trademark, but “for VCV Rack” is acceptable for promoting a plugin.

The Plugin Licensing page says a GPLv3+ plugin is allowed and recommended, and that derivative works must stay GPLv3. Its ethics guidelines forbid cloning brand names, model names, logos, panel designs or component layouts.

The SDK’s LICENSE-dist lists the libraries inside libRack: GLEW, GLFW (zlib), jansson (MIT), OpenSSL (Apache-2.0), curl, Zstandard, libarchive, speexdsp, libsamplerate, RtMidi, RtAudio, NanoVG and NanoSVG (zlib), Blendish (MIT), osdialog (CC0), pffft, fuzzysearchdatabase (BSD-3-Clause), ghc::filesystem (MIT), tinyexpr (zlib) and SIMDe (MIT). Rack distributes these inside its own binaries. RackPy does not redistribute them.

Official sample sources¶

upstream/examples.json gives every official code sample a stable ID, a source anchor, a content hash, a classification and an example task. It records 77 samples: 69 code blocks from six manual pages and 8 templates generated by helper.py. Fourteen other manual pages contain no code blocks and are listed as such.

bin/manual-sources capture downloads the pages into a cache outside git. bin/manual-sources check re-derives every block hash and fails on any changed, added or removed block. A change in the rest of the page is only reported.

The manual’s license is unclear¶

  • No manual page displays any license.

  • The manual index contains this statement inside an HTML comment, so readers never see it: “All documentation text in the VCV Manual under the https://vcvrack.com/manual/ URL is licensed under CC BY-SA 4.0 … Images such as screenshots and logos are licensed by their respective owner.”

  • VCV publishes no public repository for the manual (checked gh repo list VCVRack), so no source revision or license file exists.

  • A code search found no VCV-published GPL copy of the tutorial or guide code.

A hidden comment shows intent, but it is not clearly a published grant. The owner therefore chose not to depend on it: RackPy writes original examples for the features these samples demonstrate (port_gate: original-example) and links to the manual sections. It does not copy or adapt the manual’s code or text. Shell commands, transcripts and configuration snippets get RackPy equivalents in the same way. See ADR 001.

The recorded hashes still matter: they tell an example task which features the live manual teaches, and bin/manual-sources check reports when that changes.

helper.py templates are clear¶

helper.py is byte-identical in the SDK and in the pinned Rack tree (5d9f058e…1fa12). Rack’s license covers its source, so the template text it generates is GPL-3.0-or-later. RP-33 may port the createplugin and createmodule templates with an attribution header naming the Rack commit and listing the changes.

Source offer and notices¶

For each release, RackPy will publish the complete corresponding source as a tagged commit and a source archive next to the binaries (GPLv3 section 6(d)). Every binary artifact will contain:

  • LICENSE (GPL-3.0-or-later) and NOTICE;

  • a generated third-party license manifest for exactly the files it contains, including the bundled Python runtime and standard library;

  • the Rack commit and SDK digest it was built against.

RP-39, RP-40 and RP-41 implement this per platform. RP-44 checks it before release. Signing, publishing and registering names need owner approval.

Linux release candidates (RP-39)¶

bin/rackpy-release build makes these from a clean checkout. Every plugin package and the runtime bundle contain:

File

What it is

LICENSE, NOTICE

RackPy’s GPL-3.0-or-later license and notice

licenses/THIRD-PARTY-NOTICES.md

Each third-party component, its licenses, the file with its text, and what uses it; generated from the runtime’s own build metadata (PYTHON.json of the same python-build-standalone build, pinned in packaging/inputs.json)

licenses/python/

The license texts of CPython and of each library linked into it: OpenSSL 3 (Apache-2.0), libffi, expat, mpdecimal, liblzma, bzip2, zlib and zlib-ng, zstd, libuuid, libedit, ncurses, and SQLite (public domain)

licenses/pybind11-LICENSE

pybind11 (BSD-3-Clause), compiled into rackpy_host.so

licenses/rack-sdk-headers.txt

The notices of the third-party code in the Rack SDK’s headers that can be compiled in: jansson (MIT), SIMDe (MIT) and sse_mathfun (zlib), copied from the pinned SDK

licenses/FILES.json

Every file of that artifact with its SHA-256 and the components it is made from, and the build’s inputs: RackPy commit, Rack commit, SDK archive digest, CPython archive digest and toolchain. A file no rule covers fails the build.

Left out of the bundled CPython: _dbm (Berkeley DB, under the Sleepycat license, which adds its own source obligations), _tkinter with Tcl/Tk and their libraries (Tk’s event loop cannot run inside Rack), tkinter, idlelib and turtledemo, which need them, and pip and ensurepip (pip cannot install into a running Rack, and vendors further libraries). The build fails if the pinned runtime changes so that these no longer match.

The corresponding source is rackpy-<version>-source.tar.gz, git archive of the whole commit. No artifact contains a Rack SDK archive, Rack or Fundamental binaries, VCV artwork files (the documentation’s screenshots of Rack in use, above, are the only images of Rack), or a path of the computer that built it; the build checks the last.

Names must follow the trademark rules above: never “VCV” in a product name, and no VCV logos. A 2026-10-30 PyPI search and JSON request also found no published rackpy project. The owner approved reserving the name that day; this is not a claim that the name has been reserved or approval to publish an unfinished package. PyPI’s name-retention policy classifies an empty or nonfunctional package as name squatting, so do not publish such a placeholder.

Open questions for the owner¶

  1. User plugins written with RackPy. User scripts run in the same process as GPL code and call it intimately. The FSF view is that such plugins are usually derivative works. Decide what RackPy’s documentation tells plugin authors about licensing their scripts, and whether you want a linking or plugin exception for user scripts.

  2. Commercial use. VCV’s commercial plugin licence also covers the Component Library graphics. RackPy is GPL. Decide whether RackPy says anything about commercial plugins built with it.
