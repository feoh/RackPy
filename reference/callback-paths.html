Public virtual execution paths¶

Generated by bin/generate_bindings.py from bindings/manifest.json; do not edit. Domain classification: bin/callback-matrix and upstream/callback-rules.json.

All 439 public virtual declarations, including deprecated overloads, destructors and value virtuals. The denominator is unchanged. No entry is promoted to verified by this report.

Laboratory means explicitly enabled, offline and main-thread only, never Rack’s engine/driver threads. See Callbacks and the laboratory for restrictions, fidelity gaps and re-entrant dispatch (fixed by tk-rackpy-trampolines-suppress-same-object-re-entra-0abce9). Native configured/queued driver adapters are production paths; their synchronous Python paths are the laboratory drivers and devices of RP-22F (tk-rackpy-22f-laboratory-python-paths-for-audio-and-65ccf3). A callable name is not proof of an override. No plugin can subclass Rack’s Scene, RackScrollWidget or RackWidget (PRIVATE constructors) or make a usable PlugWidget subclass, so their UI virtuals map to calls on Rack’s own instances through borrowed host views (RP-28F decision, owner-approved 2026-10-26: tk-rackpy-28f-python-subclass-trampolines-for-plugw-154b61). Per-symbol semantics below retain the manifest’s adapter restrictions; implemented is not verified.

Execution domains¶

Domain

Legitimate Rack execution domain

ui

Main (UI) thread with no engine lock held. A Python override may run; the trampoline takes the GIL.

ui-exclusive

Main thread, or whichever thread called the engine method, while Rack holds the engine mutex EXCLUSIVELY and audio processing is stopped. A Python override may run, but must not call any engine method that locks (RackPy refuses it), and its run time stalls audio.

ui-shared

Main thread while Rack holds the engine mutex SHARED, so process() keeps running concurrently. A Python override may run synchronously, but must read module state through atomics or snapshots, never through fields that process() writes.

engine

Engine worker or fallback threads during processing. Production: native code only. Python only in the separately enabled RP-22 laboratory.

driver

Audio or MIDI driver threads (and, for some, the engine thread or UI under the exclusive lock). Native code only; Python receives queued notifications on the UI thread.

mixed

Reachable from both the UI thread and engine threads. Native implementation only; Python may configure the native behaviour but never runs in the call.

lifecycle

Destructor: runs on the thread that deletes the object, which Rack keeps on the main thread for widgets and modules. Trampolines release their Python state with the GIL there; production deletion paths do no Python work.

unresolved

Not yet decided. Blocks the implementation task named in the rule.

value

Not a callback: a virtual on a C++ exception or value type. RackPy translates or wraps it; Python never overrides it.
