rackpy.plugin¶

Add this plugin’s models to Rack. Available inside Rack only.

A RackPy plugin’s trusted entry module adds its models while Rack loads the plugin, and plugin.json’s "modules" must list exactly the same slugs. A model’s modules come from a function or from a ModuleClass. See the how-to page Register models. The raw layer is rackpy.raw.plugin.

class rackpy.plugin.ModuleClass(module: rackpy.engine.Module)¶

A model’s module written as a class: one instance per module Rack creates.

Override configure() to set the module up, as Module.create’s constructor callback would, and to_json() and from_json() for its custom state. The instance lives as long as Rack’s module, and module is that module.

add_model(slug: str, module: collections.abc.Callable[[rackpy.engine.Module], object] | type[ModuleClass], *, widget: collections.abc.Callable[[rackpy.engine.Module | None], rackpy.raw.app.ModuleWidget] | None = None, hp: int = 4) → rackpy.raw.plugin.Model¶

Add a model. Rack builds one of its modules, and its widget, whenever it needs one.

module is either Module.create’s constructor callback, module(m), or a ModuleClass subclass. widget is a rackpy.raw.app.ModuleWidget subclass, or a function, that Rack calls with the module (None for a module browser preview); the widget calls self.set_module(module) first, as Rack’s do. Without widget the module gets a plain panel hp wide. Call this only from the entry module while Rack loads the plugin.

set_settings_handlers(*, to_json: collections.abc.Callable[[], object] | None = None, from_json: collections.abc.Callable[[rackpy.types.JSON], object] | None = None) → None¶

Save plugin-wide settings in Rack’s settings.json, under this plugin’s slug.

Rack calls to_json() whenever it saves its settings, including as it exits; returning None keeps what is stored. It calls from_json(data) once, right after the plugin initializes, if anything is stored, so set the handlers from the entry module. Errors are logged and contained. Validate data: users can edit the file.

rackpy.plugin.on_destroy(callback: collections.abc.Callable[[], None]) → collections.abc.Callable[[], None]¶

Run callback when Rack calls the plugin’s destroy(), as it exits.

That is after rackpy.runtime.on_context_closing(): every handle to a Rack object is stale by then, so use it for Python-side cleanup only. Callbacks run on the main thread, most recently registered first; one that raises is logged and the others still run. Returns callback, so it works as a decorator.
