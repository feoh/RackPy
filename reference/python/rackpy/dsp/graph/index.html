rackpy.dsp.graph¶

DSP graphs: a module’s per-sample processing, described in Python (RP-21).

A Graph is built from native node types: ports, parameters and controls in, arithmetic, oscillators and Rack’s own triggers in between, outputs and lights out. Python only describes the graph; it never runs per sample. Arbitrary Python functions are not compiled: an expression on signals, such as a * b + 1, builds nodes, and anything else (if signal:, math.sin(signal)) is refused.

Every edge carries a polyphonic signal of 0 to 16 channels per frame, as Rack’s cables do. Inputs carry their cable’s channels; a mono operand broadcasts across the other’s channels, and channels missing from a shorter operand read 0 V. Feedback within the module needs an explicit Graph.delay() of one sample: a cycle without one is refused, with its path, rather than given hidden latency.

A graph may also exchange signals with the modules beside it, through Rack’s expanders: Graph.expander_send() writes a signal into a lane of the neighbour’s "rackpy.graph" message, and Graph.expander_receive() reads what the neighbour sent, exactly one frame later, as Rack’s double buffers deliver it (RP-23B).

Graph.plan() validates the graph and lowers it to a Plan, the description its execution tiers share. Graph.compile() turns it into a native kernel run by the plan interpreter on Rack’s engine thread, for Module.set_kernel; rackpy.dsp.graph_reference evaluates it offline, for tests and teaching; rackpy.dsp.graph_codegen emits a compiled tier that composes the nodes statically.

This module is pure Python and works outside Rack, except for Graph.compile().

class rackpy.dsp.graph.Plan¶

A validated graph, lowered for execution.

nodes run in order once per frame; each reads only earlier nodes’ signals, except that a delay node gives the signal latches feeds it, as of the end of the previous frame. After every node has run, each (delay, source) latch stores the source’s signal for the next frame.

expander_receive(side: int, lane: int = 0) → Signal¶

What the neighbour on side (0 left, 1 right) sent in lane, one frame later, read once.

The module must hold "rackpy.graph" messages with room for the lane on that side (rackpy.engine.expanders.graph_messages()); the signal has 0 channels whenever nothing arrived.

audio_output(channel: int, signal: Signal | float) → None¶

Send the sum of signal’s channels to a device output, once per channel.

Device samples are in units of full scale 1; scale voltages as needed.

light(index: int, brightness: Signal | float) → None¶

Sets a light’s brightness from channel 0 of brightness, once per light.

expander_send(side: int, signal: Signal | float, lane: int = 0) → None¶

Sends signal to the neighbour on side (0 left, 1 right) in lane, once per lane.

It arrives one frame later, at the neighbour’s expander_receive on the facing side. It is written only if the neighbour is a RackPy module, its facing expander points back to this module, and it holds "rackpy.graph" messages with room for the lane; otherwise nothing is sent.

compile() → _rackpy_host.dsp.Kernel¶

The graph as a native kernel, run by the plan interpreter: hand it to Module.set_kernel.

The plan is checked again natively, and its kernel allocates all its state now, on the main thread. Its fields are the ports, params and lights the graph uses, which set_kernel checks against the module; its controls change with Kernel.set. Available inside Rack only.

plan() → Plan¶

Validates the graph and lowers it: see Plan. Raises GraphError.
