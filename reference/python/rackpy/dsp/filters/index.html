rackpy.dsp.filters¶

Rack’s filters: RC, exponential, peak, slew, IIR and biquad (RP-18C).

Rack’s own objects (rack::dsp, also available as rackpy.raw.dsp), each holding its C++ state. For vectors of four, subscript the templates: TBiquadFilter[float_4]; IIR filters of any order from 2 to 8 are IIRFilter[b_order, a_order]. process_block() runs a float filter over a whole buffer natively. For design, analysis and offline processing; per-sample audio belongs in a native kernel. Available inside Rack only.

type rackpy.dsp.filters.TimedFilter = ExponentialFilter | PeakFilter | SlewLimiter | ExponentialSlewLimiter¶

The float filters whose process takes a time step.

rackpy.dsp.filters.process_block(filter: TimedFilter, in_: collections.abc.Buffer, out: collections.abc.Buffer, delta_time: float) → None¶
rackpy.dsp.filters.process_block(filter: rackpy.raw.dsp.IIRFilter_3_3_float, in_: collections.abc.Buffer, out: collections.abc.Buffer) → None

Run a float filter over every sample of in_, writing out, natively.

Each sample goes through the same Rack call as filter.process, in order, so the results and the filter’s final state are exactly those of a Python loop of process calls, only much faster. in_ and out are float32 buffers; out may be in_. The exponential, peak and slew filters need delta_time; the IIR and biquad filters take none. RC filters have no single output, so they are not supported.

BiquadFilter and the 3-3 IIR filter are typed; other IIRFilter[b_order, a_order] instantiations are created by a template, so type checkers see them as Any. Other objects raise TypeError at runtime.
