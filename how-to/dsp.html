Process audio¶

Implemented (RP-17A, RP-17B), Linux x86_64 inside Rack Free 2.6.6. Two built-in kernel types and kernels you write in C++. Rack’s DSP helpers (filters, FFTs, MinBLEP, resamplers, ring buffers, …) are bound for Python (RP-18, RP-19) for design, analysis and tests, and its SIMD vectors too (RP-20). DSP graphs built in Python run as kernels too, through the native plan interpreter or compiled into a kernel library (RP-21).

Rack calls every module’s process() once per sample, tens of thousands of times a second, on its engine thread. Python is far too slow and too unpredictable for that (performance budgets), so in RackPy the code that runs there is native: a kernel. Python picks a kernel type, wires it to the module’s ports, parameters and lights by index, and hands it to the module:

module_kernel.py · Runs inside Rack; tested against the built plugin¶
from rackpy.dsp.kernel import Gain, Sine
from rackpy.engine import Module


def voice(module: Module) -> None:
    module.config(num_params=2, num_inputs=1, num_outputs=2)
    module.config_param(0, -2, 2, 0, "Pitch", " V")
    module.config_param(1, 0, 1, 0.5, "Level")
    module.config_input(0, "V/oct")
    module.config_output(0, "Sine")
    # Rack's engine runs this native kernel every frame; Python never runs there.
    module.set_kernel(Sine(pitch_input=0, pitch_param=0, output=0, amplitude=5.0))


module = Module.create(voice)
try:
    kernel = module.kernel
    assert kernel is not None and kernel.type is Sine
    kernel.set("amplitude", 2.5)  # a control: reaches the kernel at a frame boundary
    assert kernel.values["amplitude"] == 2.5
    module.set_kernel(Gain(input=0, output=1, param=1))  # replaces the Sine kernel
    assert not kernel.alive and module.kernel is not None and module.kernel.type is Gain
finally:
    module.close()

Warning

Python process() is laboratory only, explicitly enabled by trusted code for offline experiments and tests on the main thread. The callback laboratory never runs in Rack’s engine or driver threads; a model/patch cannot create or enable a laboratory module. Normal-mode Python audio overrides are rejected. Neither laboratory timings nor the bound DSP helpers make Python production-real-time safe.

Kernels and their fields¶

rackpy.dsp.kernel has the kernel types. Calling one with keyword arguments makes a kernel:

  • Gain(input=, output=, param=-1, gain=1.0) multiplies each channel of the input by gain, and by the parameter’s value if param names one. The output gets the input’s channel count.

  • Sine(output=, pitch_input=-1, pitch_param=-1, amplitude=5.0) is a sine oscillator for each channel of a V/oct pitch input (0 V is C4), at least one; pitch_param adds a parameter’s value to the pitch.

A type’s fields list what it takes: ports, parameters and lights by index (-1 for “none” where a field is optional), and numbers. controls are the numbers you may change later. Bad fields raise TypeError or ValueError when you create the kernel; module.set_kernel(kernel) then checks the indices against the module’s configuration (ValueError names the field), so configure the module first.

Changing a running module¶

kernel.set("amplitude", 2.5) changes a control. While Rack’s engine runs the module, the value goes through a bounded queue and reaches the kernel at the next frame boundary, before it processes that frame. The queue holds CONTROL_CAPACITY (256) values; if the engine has not consumed them, set raises ValueError rather than wait. Parameters, ports and lights the kernel reads change as usual, through Rack.

module.set_kernel(other) replaces the kernel at a frame boundary; the old one is deleted on the main thread later, never on the audio thread. Its Python handle stops working (alive is False). A kernel belongs to one module: make a new one for each. module.kernel returns the current kernel.

Reset, sample rate, bypass and failures¶

Rack’s Initialize resets the kernel, and a sample-rate change reaches it before the next frame; neither runs Python. A bypassed module does what Rack does for bypass (its bypass routes), and the kernel is not called. If a kernel reports a failure, RackPy silences the module’s outputs, records a kernel_failed diagnostic (rackpy.runtime.diagnostics()), and stops calling it; module.kernel_failed is then True until Initialize or set_kernel.

For bypass behavior other than copying routes (C++ plugins override processBypass), give the module a second kernel with module.set_bypass_kernel(kernel). While the module is bypassed, Rack’s engine runs that kernel instead of copying the routes, with the same frame boundary handover, controls, reset, sample-rate and failure handling as set_kernel (module.bypass_kernel, module.bypass_kernel_failed). The kernel the module runs unbypassed is not called. A compiled graph is a convenient bypass kernel:

bypass_kernel.py · Runs inside Rack; tested against the built plugin¶
from rackpy.dsp.graph import Graph
from rackpy.engine import Module

through = Graph()
through.output(0, through.input(0) * through.param(0))
bypassed = Graph()
bypassed.output(0, -bypassed.input(0))  # bypassed: the input, inverted, at unity gain


def inverter(module: Module) -> None:
    module.config(num_params=1, num_inputs=1, num_outputs=1)
    module.config_param(0, 0, 1, 1, "Level")
    module.set_kernel(through.compile())
    # Rack's engine runs this one instead of copying bypass routes while the module is bypassed.
    module.set_bypass_kernel(bypassed.compile())


module = Module.create(inverter)
try:
    kernel, bypass = module.kernel, module.bypass_kernel
    assert kernel is not None and bypass is not None and bypass is not kernel
    assert not module.bypass_kernel_failed
finally:
    module.close()

What it costs¶

On the planning machine (not controlled hardware; the raw data and environment are in benchmarks/rp17-kernel-overhead.json), RackPy’s kernel path costs 0.64 ns per frame on top of the same DSP written as a plain C++ module for a sine oscillator (+7.6%), and 0.80 ns for a one-multiply gain. That is within the budgets frozen in ADR 004 (at most 1.5 ns, and 10% for kernels at least as costly as a sine). The built-in kernels do more than that reference (polyphony, an optional parameter), which adds about 1.5 ns per frame on these workloads.

Threads¶

Create kernels, call set_kernel, set_bypass_kernel and set on Rack’s main thread (ThreadError otherwise). The engine thread only runs the kernel. A test in RackPy’s suite runs the kernel path under an allocation and lock detector and requires zero heap, lock, write or GIL calls on it, bypassed frames included.

Write a kernel in C++¶

When the built-in kernels are not enough, write your own in C++ and ship it in your plugin as a kernel library. RackPy loads the libraries listed in rackpy-loader.json before your entry module runs:

"kernels": ["kernels/kernels_example.so"]

A library includes RackPy’s rackpy/kernel.hpp (from RackPy’s native/include) after <rack.hpp>, implements rackpy::Kernel, and registers its types with RACKPY_KERNEL_LIBRARY. It may also add node types for DSP graphs with rackpy/graph.hpp and RACKPY_GRAPH_NODES. This wavefolder, with a graph node version of the same fold and a sample-and-hold node, is the example RackPy’s tests build and run in Rack:

// SPDX-License-Identifier: GPL-3.0-or-later
// An example RackPy kernel library (RP-17B): a wavefolder. Built with the
// Rack SDK's plugin flags, listed in rackpy-loader.json as
// "kernels": ["kernels/kernels_example.so"], and used from Python as
// rackpy.dsp.kernel.load("example.Fold"). It also adds graph node types
// (RP-21C): Graph.node("example.Fold", ...) and Graph.node("example.Hold", ...).
#include <rack.hpp>
#include <rackpy/graph.hpp>
#include <rackpy/kernel.hpp>

#include <cmath>

namespace {

/** Folds each channel of the input back into [-limit, limit], after a gain. */
struct Fold : rackpy::Kernel {
	int input, output;
	float gain, limit;

	explicit Fold(const std::vector<double>& v)
		: input((int) v[0]), output((int) v[1]), gain((float) v[2]), limit((float) v[3]) {
		if (limit <= 0.f)
			throw std::invalid_argument("example.Fold: limit must be positive");
	}

	static float fold(float x, float limit) {
		float period = 4.f * limit;
		float t = std::fmod(x + limit, period);
		if (t < 0.f)
			t += period;
		return t < 2.f * limit ? t - limit : 3.f * limit - t;
	}

	// Runs on Rack's engine thread every frame: no allocation, locks, IO or exceptions.
	bool process(rack::engine::Module& m, const rack::engine::Module::ProcessArgs&) noexcept override {
		rack::engine::Input& in = m.inputs[input];
		rack::engine::Output& out = m.outputs[output];
		int channels = in.getChannels();
		out.setChannels(channels);
		for (int c = 0; c < channels; c++)
			out.setVoltage(fold(in.getVoltage(c) * gain, limit), c);
		return true;
	}

	void setControl(int slot, double value) noexcept override {
		if (slot == 0)
			gain = (float) value;
		else if (slot == 1 && value > 0)
			limit = (float) value;
	}
};

/** The same fold as a graph node: each channel of its input, times `drive`, folded into [-limit, limit]. */
struct FoldNode : rackpy::graph::Node {
	float drive, limit;
	FoldNode(float drive, float limit) : drive(drive), limit(limit) {}
	void process(rackpy::graph::Signal& out, const rackpy::graph::Signal* const* in,
		const rack::engine::Module::ProcessArgs&) noexcept override {
		rackpy::graph::map1(out, *in[0], [this](float x) { return Fold::fold(x * drive, limit); });
	}
};

/** Sample and hold: each channel of input 0, taken when the same channel of input 1 rises to 1 V. */
struct Hold : rackpy::graph::Node {
	rack::dsp::SchmittTrigger trigger[rackpy::graph::MAX_CHANNELS];
	rackpy::graph::Signal held;
	void process(rackpy::graph::Signal& out, const rackpy::graph::Signal* const* in,
		const rack::engine::Module::ProcessArgs&) noexcept override {
		int n = std::max(in[0]->channels, in[1]->channels);
		held.channels = n;
		for (int c = 0; c < n; c++)
			if (trigger[c].process(rackpy::graph::lane(*in[1], c)))
				held.v[c] = rackpy::graph::lane(*in[0], c);
		out = held;
	}
	void reset() noexcept override {
		held = rackpy::graph::Signal();
		for (auto& t : trigger)
			t.reset();
	}
};

}  // namespace

RACKPY_GRAPH_NODES(registrar) {
	registrar.add(rackpy::graph::NodeType{
		"Fold",
		"Each channel of its input, times drive, folded back into [-limit, limit].",
		1,
		{"drive", "limit"},
		[](const std::vector<double>& a) -> std::unique_ptr<rackpy::graph::Node> {
			if (a[1] <= 0)
				throw std::invalid_argument("example.Fold: limit must be positive");
			return std::make_unique<FoldNode>((float) a[0], (float) a[1]);
		},
	});
	registrar.add(rackpy::graph::NodeType{
		"Hold",
		"Sample and hold: input 0, taken when input 1 rises to 1 V (Rack's SchmittTrigger).",
		2,
		{},
		[](const std::vector<double>&) { return std::unique_ptr<rackpy::graph::Node>(new Hold); },
	});
}

RACKPY_KERNEL_LIBRARY("example", registrar) {
	registrar.add(rackpy::KernelType{
		"Fold",
		"Folds each input channel back into [-limit, limit] after a gain.",
		{
			{"input", rackpy::Field::INPUT, 0, true, "the input port"},
			{"output", rackpy::Field::OUTPUT, 0, true, "the output port"},
			{"gain", rackpy::Field::NUMBER, 1, false, "applied before folding (a control)"},
			{"limit", rackpy::Field::NUMBER, 5, false, "the fold threshold in volts (a control)"},
		},
		{"gain", "limit"},
		[](const std::vector<double>& v) { return std::make_unique<Fold>(v); },
	});
}

Python then uses it like a built-in type, under the library’s namespace: rackpy.dsp.kernel.load("example.Fold") returns the type, and module.set_kernel(Fold(input=0, output=0, limit=5)) gives a module the kernel (RackPy’s test tests/dsp/in_rack_libraries/test_libraries.py does exactly this inside Rack).

Build it as you would a Rack plugin: with the Rack SDK’s compiler flags (-fPIC -O3 -march=nehalem -funsafe-math-optimizations and the rest of compile.mk), -I the SDK’s include and dep/include and RackPy’s native/include, linked as a shared library against -lRack with -static-libstdc++ -static-libgcc, as for any plugin. RackPy’s own build does exactly that for the example (rackpy_kernels_example in CMakeLists.txt).

In a plugin project made by bin/rackpy-plugin, put the source in kernels/NAME.cpp and list NAME under "kernels" in rackpy-plugin.json. RackPy’s build compiles the examples’ libraries this way, and bin/rackpy-plugin build --kernels DIR copies DIR/NAME.so into the plugin’s kernels/ folder and lists it in rackpy-loader.json. The polyphony, dsp and expanders examples are such projects.

The rules:

  • process, reset, sampleRateChange and setControl run where audio is produced: no allocation, locks, IO, logging or exceptions (they are noexcept). Allocate in the constructor. Return false from process to fail, as described above.

  • The constructor runs on the main thread when Python creates the kernel. If it throws, Python gets ValueError with your message.

  • Names are identifiers. Python sees namespace.Name. rackpy and names starting with rackpy_ are reserved.

  • A library loads all or nothing, kernel types and graph node types together. If it cannot be loaded, was built for another kernel ABI (rackpy::KERNEL_ABI) or graph ABI (rackpy::graph::GRAPH_ABI), defines only part of RACKPY_GRAPH_NODES, throws while registering, repeats a type name, uses a reserved namespace or a bad name, gives a node type more than 8 inputs or repeated argument names, or its path leaves the plugin folder, Rack’s log says RackPy skipped kernel library ... with the reason, none of its types appear, and the other libraries still load.

  • Libraries stay loaded until Rack exits. They are trusted code from your plugin, like your Python.

Exchange expander messages from C++¶

A kernel (or a graph node) in a library can exchange messages with the modules beside it through Rack’s expanders, under a message layout of its own: a schema, named in your library’s namespace, whose size and meaning you define. RackPy does the checks Rack leaves to every module, before your code touches a neighbour’s buffer: that the neighbour is a RackPy module, that it points back, and that its buffers have your schema and are big enough. Include rackpy/expanders.hpp, define RACKPY_EXPANDERS once, and RackPy gives your library its expander services when it loads it. This library is RackPy’s tested example:

// SPDX-License-Identifier: GPL-3.0-or-later
// An example RackPy kernel library that exchanges expander messages with a
// schema of its own (RP-23C). "levels.Send" writes its input's channel count
// and voltages to the module on its right; "levels.Receive" outputs what
// arrives from its left, one frame later. The receiver owns the messages:
// its Python code gives the side it receives on two "levels.Levels" buffers
// of 17 values, allocate_messages(module.left_expander, "levels.Levels", 17).
#include <rack.hpp>
#include <rackpy/expanders.hpp>
#include <rackpy/kernel.hpp>

#include <algorithm>
#include <stdexcept>

namespace {

/** The layout this library defines for "levels.Levels": a channel count, then the voltages. */
constexpr size_t SIZE = 1 + rack::engine::PORT_MAX_CHANNELS;

const rackpy::expander::Schema* levels(const char* who) {
	// Main thread: the kernel's constructor. Null if RackPy gave this library no expander services.
	const rackpy::expander::Schema* schema = rackpy::expander::schema("levels.Levels");
	if (!schema)
		throw std::invalid_argument(std::string(who) + ": RackPy gave this library no expander services");
	return schema;
}

struct Send : rackpy::Kernel {
	int input;
	const rackpy::expander::Schema* schema = levels("levels.Send");
	rackpy::expander::Link link;  // RackPy's, to check the neighbour only when it changes

	explicit Send(const std::vector<double>& v) : input((int) v[0]) {
		if (input < 0)
			throw std::invalid_argument("levels.Send: input must be wired");
	}

	// Rack's engine thread, every frame: no allocation, locks, IO or exceptions.
	bool process(rack::engine::Module& m, const rack::engine::Module::ProcessArgs&) noexcept override {
		// The right neighbour's producer buffer (and the flip requested), only if the neighbour is a RackPy
		// module whose left side holds "levels.Levels" messages of at least SIZE values. Otherwise nothing.
		if (float* message = rackpy::expander::send(m, 1, schema, SIZE, link)) {
			rack::engine::Input& in = m.inputs[input];
			int channels = in.getChannels();
			message[0] = (float) channels;
			for (int c = 0; c < channels; c++)
				message[1 + c] = in.getVoltage(c);
		}
		return true;
	}
};

struct Receive : rackpy::Kernel {
	int output;
	const rackpy::expander::Schema* schema = levels("levels.Receive");
	rackpy::expander::Link neighbour, own;

	explicit Receive(const std::vector<double>& v) : output((int) v[0]) {
		if (output < 0)
			throw std::invalid_argument("levels.Receive: output must be wired");
	}

	bool process(rack::engine::Module& m, const rack::engine::Module::ProcessArgs& args) noexcept override {
		// This module's consumer buffer on the left: what the neighbour wrote during the previous frame.
		float* message = rackpy::expander::receive(m, 0, schema, SIZE, args.frame, neighbour, own);
		int channels = message ? std::min(std::max((int) message[0], 0), rack::engine::PORT_MAX_CHANNELS) : 0;
		rack::engine::Output& out = m.outputs[output];
		out.setChannels(std::max(channels, 1));
		for (int c = 0; c < std::max(channels, 1); c++)
			out.setVoltage(c < channels ? message[1 + c] : 0.f, c);
		if (message)
			message[0] = 0.f;  // read once: a neighbour that stops sending is heard as silence
		return true;
	}
};

}  // namespace

RACKPY_KERNEL_LIBRARY("levels", registrar) {
	registrar.add(rackpy::KernelType{
		"Send",
		"Sends its input's channels to the module on its right, as a levels.Levels message.",
		{{"input", rackpy::Field::INPUT, 0, true, "the input port"}},
		{},
		[](const std::vector<double>& v) { return std::make_unique<Send>(v); },
	});
	registrar.add(rackpy::KernelType{
		"Receive",
		"Outputs the levels.Levels message from the module on its left, one frame later.",
		{{"output", rackpy::Field::OUTPUT, 0, true, "the output port"}},
		{},
		[](const std::vector<double>& v) { return std::make_unique<Receive>(v); },
	});
}

// RackPy gives this library its expander services when it loads it.
RACKPY_EXPANDERS

In Python, the receiving module owns the messages of the side it receives on, as in Rack: give it two buffers of your schema with allocate_messages(module.left_expander, "levels.Levels", 17) (rackpy.engine.expanders) before Rack’s engine runs the module, and use the kernels like any others: load("levels.Send")(input=0). RackPy’s test tests/dsp/in_rack_libraries/test_libraries.py runs this pair in Rack’s own engine.

The contract:

  • schema(name) runs on the main thread, in a kernel’s constructor; it returns null when RackPy gave the library no services (throw, as the example does, so that Python gets ValueError). A name is 1 to 64 letters, digits, _, . or -; use your namespace as a prefix.

  • send(module, side, schema, size, link) returns the neighbour’s producer buffer and requests the flip; receive(module, side, schema, size, frame, neighbour, own) returns this module’s consumer buffer. Either returns null when the check fails: write or read nothing then. Both run on Rack’s engine thread without locks or allocation. Keep the Links in your kernel, one per call site; RackPy uses them to check a neighbour only when it changes. Pass ProcessArgs::frame to receive, so that RackPy can copy the message for Python’s snapshots before you change anything.

  • A message arrives one frame after it was written, whatever the order and the number of engine threads, because Rack swaps the two buffers after every module of the frame has run. Mark what you have read (the example zeroes its count), or a neighbour that stops sending is heard again.

  • The buffers belong to the receiving RackPy module. Never assign a RackPy module’s expander slots, flip flags or buffers yourself, never keep a buffer pointer past the frame, and write only within size values.

  • Rack’s own expander API stays available for another plugin’s modules: check neighbour->model first, then interpret its void* as that plugin documents, as Rack’s manual describes. RackPy cannot check that for you, and Python never sees such a pointer except as an opaque ForeignMessage.

  • A library built for another rackpy::expander::EXPANDER_ABI, or that defines only part of RACKPY_EXPANDERS, is skipped as a whole, with the reason in Rack’s log.
