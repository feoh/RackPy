Pass signals to the module beside yours¶

In Rack, two modules placed edge to edge are each other’s expanders: each module sees its left and right neighbours. A module can send its neighbour messages, or read the neighbour’s knobs and ports directly. This guide does both.

Status: Linux x86_64, Rack Free 2.6.6, tested in Rack (examples/expanders).

Send messages with graphs¶

Rack’s expander messages use two buffers per side, owned by the receiving module: the sender writes into one while the receiver reads the other, and Rack swaps them after every module of a frame has run. A message arrives exactly one frame after it was sent, however Rack orders the two modules.

  1. The receiver gives its side buffers, in its constructor callback, with rackpy.engine.expanders.graph_messages(): here, on its left, with room for two signals (lanes).

    examples/expanders/pythonpath/rackpyexpanders/receiver.py · from an example plugin tested in Rack¶
    def configure(module: Module) -> None:
    """Rack calls this to build each module: configure its controls here."""
    module.config(0, 0, len(Output), len(Light))
    module.config_output(Output.RECEIVED, "Received signal")
    module.config_light(Light.LINK, "Source's level")
    graph_messages(module.left_expander, graphs.LANES)  # the buffers the Source writes into
    module.set_kernel(GRAPH.compile())

  2. The sender’s graph sends each lane to its right neighbour with expander_send, and the receiver’s graph receives it from its left with expander_receive:

    examples/expanders/pythonpath/rackpyexpanders_graphs.py · from an example plugin tested in Rack¶
    def source_graph() -> Graph:
    g = Graph()
    level = g.param(LEVEL)
    scaled = g.input(SIGNAL) * level
    g.output(SCALED, scaled)
    g.expander_send(RIGHT, scaled, SIGNAL_LANE)
    g.expander_send(RIGHT, level, LEVEL_LANE)
    return g
    examples/expanders/pythonpath/rackpyexpanders_graphs.py · from an example plugin tested in Rack¶
    def receiver_graph() -> Graph:
    g = Graph()
    g.output(RECEIVED, g.expander_receive(LEFT, SIGNAL_LANE))
    # Lit as brightly as the Source's LEVEL; with no Source on the left nothing arrives: 0 channels, dark.
    g.light(LINK, g.expander_receive(LEFT, LEVEL_LANE))
    return g

RackPy checks the neighbour on the engine thread before writing: if it is not a RackPy module, or its buffers are of another kind or too small, nothing is written, and the receiver’s signal has 0 channels. Moving the modules apart does the same at once. Graphs has the details, and how to exchange messages from a C++ kernel is in process audio.

Read the neighbour directly, in C++¶

A C++ module can read its neighbour’s parameters and ports through Rack’s leftExpander.module. That happens on the engine thread, where Python never runs, so in RackPy it is a C++ kernel’s job: the example’s Peeker (kernels/expanders.cpp) checks that its left neighbour is this plugin’s Source, then reads its knob and output.

The value it reads is from this frame or the last, because Rack may process the two modules in either order, or at once on two threads. When the timing matters, use messages.

From Python, on the main thread¶

Python can look at a module’s expanders too (rackpy.engine.expanders): which module is beside it, and the contents of a message buffer while Rack’s engine is not running the module. RackPy refuses to touch a buffer that the engine thread is writing, rather than read it while it changes. Python is for setting up and inspecting; the per-sample exchange is native.
