Use audio and MIDI devices¶

Rack talks to sound cards and MIDI devices through drivers, devices and ports, as its Core Audio and MIDI-CV modules do. This guide shows which way to use each, depending on whether the data must follow the audio or only reach your Python.

Status: Linux x86_64, Rack Free 2.6.6. MIDI and Python-driven audio devices are tested in Rack. A module’s own audio port is work in progress: tested on Rack’s loopback and virtual devices, never with a physical sound card (audio).

Receive MIDI in Python¶

Subclass midi.Input and override on_message. Rack delivers MIDI on its driver’s thread, where Python never runs, so RackPy queues each message and calls on_message on Rack’s main thread at its next frame. A full queue drops the message and counts it, rather than block the MIDI thread.

A port that collects the notes it receives, on Rack’s Loopback driver · Runs inside Rack; tested against the built plugin¶
from rackpy.raw import midi

LOOPBACK = -12  # Rack's Loopback MIDI driver: what goes out on device N comes in on device N


class NoteLog(midi.Input):
    """Collects the notes that arrive. RackPy calls on_message on the UI thread, not the MIDI thread."""

    def __init__(self) -> None:
        super().__init__()
        self.notes: list[int] = []

    def on_message(self, message: midi.Message) -> None:
        if message.get_status() == 0x9 and message.get_value() > 0:  # note on
            self.notes.append(message.get_note())


def open_loopback(device_id: int) -> tuple[midi.Output, NoteLog]:
    """Call from Rack's UI thread: an output and a NoteLog on one loopback device."""
    out, log = midi.Output(), NoteLog()
    for port in (out, log):
        port.set_driver_id(LOOPBACK)
        port.set_device_id(device_id)
    return out, log


def note_on(note: int, velocity: int = 100) -> midi.Message:
    message = midi.Message()
    message.set_status(0x9)
    message.set_note(note)
    message.set_value(velocity)
    return message

Turn MIDI into voltages¶

For a gate or pitch that must change at the right sample, the messages must reach native code, not Python. Attach an empty, disconnected midi.InputQueue to the module with set_midi_input(index, queue) before Rack’s engine owns it, connect the port to a device, and give the module a kernel that reads it: the built-in rackpy.dsp.kernel.MidiToCV, which has Core MIDI-CV’s twelve outputs, or a graph’s midi_cv node (graphs). Messages longer than three bytes, SysEx included, are dropped (MIDI).

Be an audio interface¶

Module.set_audio_port(port, inputs=..., outputs=...) attaches an audio port to a module, and its kernel then exchanges samples with the device every frame: the built-in AudioInterface kernel converts as Core Audio does (a device’s full scale is 10 V), or a graph uses audio_input and audio_output. As Rack’s only audio module, it can clock Rack’s engine, as Core Audio does. The audio reference lists what is and is not established yet.

Feed a device from Python¶

A Python-driven device is a device whose samples Python produces or consumes: for tests, offline rendering, or bridging to something Rack has no driver for. Python runs on whichever thread calls Stream.process, never on a Rack audio thread:

A virtual device streams a ramp to a port that records each block’s peak · Runs inside Rack; tested against the built plugin¶
from array import array

from rackpy import audio
from rackpy.raw import audio as raw_audio

DRIVER_ID = 7001  # stored in patches: pick one no other driver uses


class Peak(raw_audio.Port):
    """A port that keeps the loudest input sample of each block a Python device delivers."""

    def __init__(self) -> None:
        super().__init__()
        self.peaks: list[float] = []

    def process_input(self, input: array[float], input_stride: int, frames: int) -> None:
        self.peaks.append(max((abs(x) for x in input), default=0.0))


def render(blocks: int) -> list[float]:
    """Call from Rack's UI thread once: a virtual device streams a ramp to a Peak port, one block at a time."""
    driver = audio.virtual_driver(DRIVER_ID, "Docs Virtual", devices=("Ramp",))
    device = driver.get_device(0)
    assert device is not None
    port = audio.open_port(DRIVER_ID, "Ramp", kind=Peak)
    with audio.Stream(device) as stream:
        for block in range(blocks):
            frames = device.block_size
            ramp = array("f", [block / blocks] * (frames * device.num_inputs))
            stream.process(frames, ramp)
    port.set_device_id(-1)
    return port.peaks

Rules for every port¶

  • Ports are made and changed on Rack’s main thread, while Rack’s window is open: a port needs Rack’s engine for timing.

  • A port saves its driver and device in to_json and finds the device again by name in from_json. Save it with your module’s state.

  • Rack’s drivers outlive the patch: RackPy gives every Python port’s device back when Rack closes, and a port you drop is deleted on the main thread.
